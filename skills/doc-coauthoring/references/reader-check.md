# 读者检查

用于检查文档能否脱离作者会话独立工作，不代替事实取证或设计批准。

## 1. 选择真实问题

围绕读者要完成的任务提出少量问题，不规定固定数量：

- 这份材料讨论什么，适用与不适用范围是什么？
- 主流程从何处开始，到何处结束，关键责任由谁承担？
- 重要约束、错误路径或生命周期规则是什么？
- 哪些是实现事实、已定决策、推断与未来提案？
- 某个关键结论的证据在哪里，哪些仍未验证？
- 读完后如何使用信息或进一步核验？

问题应检验表达效果，不暗含希望读者给出的答案。

## 2. 选择检查方式

- 获准且可用时，可交给独立读者或上下文隔离的代理。
- 给出最终文档、真实读者角色与问题，不提供作者解释、预期评分或通过暗示。
- 对事实复核者另给必要源材料，但不交付其他评审者的结论当答案。
- 工具或授权不足时做自查，并如实称为自查，不伪造独立读者结果。
- 内部材料只能交给允许访问的读者与工具，不因检查方便而外传。

## 3. 要求具体反馈

让读者提供：

1. 依据文档得出的回答及对应段落。
2. 无法回答的地方、歧义和缺失前提。
3. 文内或图文之间的矛盾。
4. 需要哪些外部知识才理解，是否符合目标读者设定。

记录实际误读，不用“很清楚”或“通过”替代逐项观察。
缺少可检查产物或必要源时指出具体缺口，不推测通过。

## 4. 修正并复查

- 定位误读原因：术语、结构、缺失事实、箭头方向或隐藏假设。
- 在正文或图注中补足必要解释，而不是只在会话里回答读者。
- 只改受影响内容，避免不必要扩写与推翻已定设计。
- 修后复查相关问题；若更改技术主张，回到来源重新核验。
- 图的语义和视觉分别按 [diagrams](diagrams.md) 检查。

## 5. 交付说明

说明检查方式、覆盖的问题、实际发现与修正，以及剩余盲点。
独立读者理解正确只支持可理解性，不证明代码运行、性能或外部事实正确。
用户明确不需要读者检查时尊重选择，但不得声称已完成该检查。
