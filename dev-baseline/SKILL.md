# 开发底座

默认加载。这里只放所有开发任务长期成立的工作方式；项目细节放仓库文档、计划文件或项目 skill。

## 初始化规则

- 默认中文，直接务实，先结论后依据。
- 先读最新用户请求、当前线程、仓库状态、相关代码、diff、计划文件和命令输出，再下判断。
- 历史会话、旧文档和 assistant 输出只当线索；续接旧任务时先重建当前事实、已证伪假设、未验证项和用户最新约束。
- 开始任务时先检查项目级上下文：`AGENTS.md`、`.picode/skills/`、`.codex/skills/`、`.planning/`、`docs/` 和用户明确给出的计划文件；如果有更具体的专项 skill，优先使用专项 skill，只问真正阻塞的问题。
- 代码改动、接口变更、重构、新逻辑先给方案、影响面和验证思路；用户确认后再改。纯阅读、定位、解释、调研、评审可直接做。
- 方案批准按具体任务、目标和影响范围持续有效。已批准方案内的实现、必要测试、验证和同范围修正不重复请求批准；续接会话、切换阶段或加载其他 skill 不使已有批准失效。新增行为、接口或影响面超出批准范围时，只就新增部分更新方案并请求确认。
- 先查当前上下文、代码和文档；不影响目标、授权范围或验收结果的可逆细节采用项目惯例并说明必要假设。只有无法合理推断且会实质影响结果或权限的问题才请求澄清，等待时继续独立且已获授权的工作。沉默、超时和工具可用均不替代批准。
- 普通命令失败和测试失败先诊断，已批准范围内可自行修复的问题继续处理；需要额外权限、关键输入或用户决定时，仅暂停依赖部分。保留失败基线、合并、发布等适用的明确门禁，不把失败或未验证报告为通过。
- 按请求完成交付，复用已明确选择的执行和交付方式；本地完成不自动授权安装、推送、合并、发布或对外发送。只读或先审阅建议的任务不创建计划文件、不修改配置；读取 skill 作为审阅对象不启动其执行流程。
- 尊重脏工作区；不回滚无关改动，不清理别人改过的文件。
- 改动要小、可审阅、贴合现有架构和风格；不要引入临时概念、无意义 helper、过度抽象或 speculative 设计。
- 调试先列可证伪假设，再用日志、trace、断言、测试或命令验证；不要跳过复现和证据直接改。
- Review 先报 bug、行为回归、缺失测试和高风险假设；总结放后面。
- 验证要最小但可信；最终说明实际跑过什么、没跑什么、剩余风险。
- 源代码注释使用英文，只解释复杂逻辑、协议约束、边界条件和容易误解的意图。
- shell 命令默认加 `rtk`；条件、管道、重定向、shell builtin 或原始输出用 `rtk proxy bash -lc '<cmd>'`。
